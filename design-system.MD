DESIGN PHILOSOPHY

Core Principles

The Homy design system embraces luxury minimalism—a balance between premium aesthetics and functional clarity.

Visual Identity:

Premium Minimalism: Luxury achieved through restraint, not decoration

Trust Through Clarity: Clean layouts with breathing room reduce cognitive load

Confidence-Driven: Large, authoritative imagery and clear CTAs guide decisions

Modern Elegance: Contemporary proportions paired with refined typography

User-Centric Hierarchy: Information architecture prioritizes discovery and comparison

Emotional Connection: Property imagery is celebrated, not merely functional

Design Personality: Sophisticated, approachable, trustworthy, contemporary

Overall Experience: Exploration feels guided but not restricted; discovery feels intuitive

Why This Design Feels Premium

Restraint in Color Palette — Monochromatic base (black/white/gray) with single accent color allows imagery to shine

Generous Whitespace — Large section gaps (80-120px) and generous padding communicate exclusivity

High-Quality Imagery — Professional photography is primary visual content, not decorative

Confident Typography — Bold headlines (700 weight) and readable body text (14-16px, 1.5-1.6 line height)

Subtle Motion — Smooth hover states and fade-in animations without being distracting

Consistent Spacing — 4px-based scale creates predictable, mathematical relationships

Accessibility-First — Large touch targets and clear focus states as standard

Blur + Overlay Rule:

Blur alone is insufficient; always pair with overlay color

Overlay opacity: 0.3 (transparent) to 0.8 (opaque)

Glassmorphism Constraints

✅ Use only for navigation bars or hero text overlays

✅ Never stack multiple blur layers

DARK MODE STRATEGY

Decision: Light Mode Only

Rationale:

Brand Alignment: Luxury minimalism communicates through clean, bright spaces

Property Photography: High-quality images are the hero element; dark mode diminishes photo impact

Real Estate Industry: Standard is light backgrounds (photography focused)

User Expectations: Property seekers expect bright, clean interfaces

Simplification: Eliminates maintenance overhead for design tokens and components

Reasoning Explained

Light backgrounds are premium: Whitespace is associated with luxury

Images are priority: Dark mode makes photographs appear dimmer

Real estate standard: Industry convention is light UI

Consistent brand: Simplified design system maintains brand integrity

Reduced complexity: One color system instead of two

Implementation

Do NOT implement dark mode

Keep all color tokens light-mode only

Remove prefers-color-scheme detection (except for reduced motion, which is orthogonal)

Set HTML background: background-color: #ffffff (no toggle needed)

If Dark Mode Required (Future)

Should the product team later request dark mode, the following approach would apply:

Token Duplication Strategy:

Create parallel token set for dark mode

Example: --color-background-light: #ffffff + --color-background-dark: #1a1a1a

Use CSS variables with media query: @media (prefers-color-scheme: dark) { ... }

Color Adjustments:

Invert lightness (swap primary black/white)

Accent orange remains constant (#ff6b35)

Increase contrast in dark mode

However, for this project: Light mode only.

DESIGN CONSTRAINTS

Strict Rules (Enforce These Always)

1. Color System

✅ Use only 5-color palette defined in Color System

✅ Never introduce new colors outside tokens

✅ All text colors from: #1a1a1a, #666666, #999999

✅ All backgrounds from: #ffffff, #f8f8f8, #f0f0f0

✅ CTA color always: #ff6b35

2. Spacing

✅ Use only 4px-based spacing scale

✅ No arbitrary padding/margins (e.g., no p-[13px])

✅ Section gaps: 60px, 80px, or 120px only

✅ Component padding: 20px, 24px, or 32px only

✅ Never mix margin and gap on same element

3. Typography

✅ Single font family (Inter) throughout

✅ Use only defined font sizes and weights

✅ No custom font sizes (no text-[17px])

✅ Headings always 700 or 600 weight

✅ Body text always 400 weight (regular)

✅ Line heights as defined (no custom values)

4. Border Radius

✅ Use only: 0px, 4px, 8px, 12px, 16px, 50%

✅ Primary card radius: 12px (do not change)

✅ Button radius: 8px (consistent)

✅ Never mix radius sizes in one component

✅ Form inputs: 8px (always)

5. Shadows

✅ Use only 5 defined shadow levels

✅ Never create custom shadows

✅ Hover = shadow elevation + color change

✅ Maximum 2 elevation levels change

✅ Never stack multiple shadows

6. Icons

✅ Use Heroicons only

✅ Never mix icon libraries

✅ Icon sizes: 16px, 20px, 24px only

✅ 8px spacing between icon and text

✅ Never use emojis as icons

7. Animation

✅ Durations: 100ms, 200ms, 300ms, 400ms only

✅ Easing: ease-out or ease-in-out only

✅ Never exceed 800ms animation duration

✅ Respect prefers-reduced-motion always

✅ No simultaneous animations (max 2)

8. Images

✅ Aspect ratios: 16:9, 4:3, 3:2, 1:1 only

✅ Border radius on images: 12px or 16px

✅ Always provide alt text

✅ Optimize file sizes (WebP primary)

✅ Dark overlay opacity: 0.3-0.4 only

9. Components

✅ Reuse components instead of duplicating

✅ Maximum 1 component per file

✅ All props typed with TypeScript

✅ Default exports only

✅ Props interface: [ComponentName]Props

10. Buttons

✅ Minimum height: 44px

✅ Sizes: small (36px), medium (44px), large (52px)

✅ Variants: primary, secondary, accent, text

✅ Always show focus state (2px outline)

✅ Hover = shadow + color change

11. Forms

✅ All inputs minimum 44px height

✅ Labels always above inputs (never placeholder)

✅ Required fields marked with asterisk (*)

✅ Error messages: 12px, red, below input

✅ Field spacing: 16px between inputs

12. Accessibility

✅ Focus outline visible (2px #1a1a1a)

✅ Minimum contrast 4.5:1 for text

✅ Touch targets 44px minimum

✅ Alt text on all images (no empty)

✅ Logical heading hierarchy (H1 → H2 → H3)

13. Containers & Grid

✅ Max container width: 1280px

✅ Gutters: 20px mobile, 40px tablet, 60px desktop

✅ 12-column grid system

✅ Column gap: 20px (mobile), 32px (desktop)

✅ Never exceed max width

14. Responsive

✅ Mobile-first design always

✅ Breakpoints: 320px, 640px, 1024px, 1280px

✅ Logical tab order maintained

✅ Text sizes scale per breakpoint

✅ Single column mobile → multi-column desktop

15. Naming

✅ Components: PascalCase.tsx

✅ Utilities: camelCase.ts

✅ Hooks: use[Name].ts

✅ Constants: [name].constants.ts

✅ One component per file rule

Anti-Patterns (Never Do These)

❌ Don't introduce new colors❌ Don't use arbitrary Tailwind values (p-[13px])❌ Don't mix multiple icon libraries❌ Don't create custom shadows❌ Don't disable focus outlines❌ Don't use placeholder as form label❌ Don't exceed 800ms animation duration❌ Don't use emojis as UI elements❌ Don't duplicate components (reuse instead)❌ Don't skip alt text on images❌ Don't create custom font sizes❌ Don't mix margin and gap on same element❌ Don't nest more than 2 levels of components without reviewing❌ Don't use absolute positioning (use flexbox/grid)❌ Don't create responsive variants outside breakpoints

DEVELOPER IMPLEMENTATION NOTES

Implementation Approach

This Design System is the single source of truth for all future component development. Every generated component must follow it exactly.

Generation Rules

1. Technology Stack

✅ Next.js App Router (do not use Pages Router)

✅ React with TypeScript

✅ Tailwind CSS only (no inline styles)

✅ No additional CSS files (except globals.css)

✅ No external UI libraries (build custom components)

2. File Output

✅ Generate .tsx components only

✅ One component per file (strict)

✅ TypeScript required (no JavaScript)

✅ Default export for components

✅ Named export for types/interfaces

3. Component Requirements

✅ Fully typed with TypeScript

✅ Props interface: [ComponentName]Props

✅ Responsive design (mobile-first)

✅ Accessibility built-in (focus states, alt text, ARIA)

✅ Animation support (with reduced-motion fallback)

4. Styling Requirements

✅ Tailwind CSS classes only

✅ Use design tokens (colors, spacing, radius, shadows)

✅ Responsive prefixes (md:, lg:, etc.)

✅ No inline styles (style prop forbidden)

✅ No CSS-in-JS or styled-components

5. Code Quality

✅ Follow component naming convention

✅ Reuse existing components (don't duplicate)

✅ Clean, readable code structure

✅ Props properly documented

✅ No prop drilling (use context if needed)

6. What NOT to Generate

❌ Do not create a new Next.js project❌ Do not generate routing (next/navigation)❌ Do not generate API routes or server actions❌ Do not generate authentication logic❌ Do not generate backend services❌ Do not generate package configuration❌ Do not generate environment files❌ Do not generate .env variables❌ Do not generate database schemas❌ Do not generate third-party integrations

Component Generation Workflow

When generating a new component:

Review Design System

Check this document for existing component spec

Verify design tokens (colors, spacing, shadows)

Confirm animation requirements

Check accessibility requirements

Check Existing Components

Search components/ folder for similar components

Reuse if 80%+ match

Avoid duplication at all costs

Plan Component Structure

Define props interface

Plan internal subcomponents (if needed)

Identify Tailwind classes

Plan responsive breakpoints

Generate Component

Use design tokens for all styling

Implement accessibility features

Add focus states and keyboard navigation

Include reduced-motion support
